# Copilot Critique

I asked Copilot to write one more test: a POST to `/api/quote` with no `coverageAmount` should return 400. **What it got right:** the test matches the requirement. It leaves out `coverageAmount` and uses valid values for `type` ("home") and `age` (40), so the only reason for a 400 is the missing field. That makes it a fair test and keeps it consistent with the rest of the suite. **What it missed:** it only checks the HTTP status code, not the validation error itself. A 400 for any other reason would still satisfy the test. **Would I ship it as-is?** No. I'd keep it, but first add a check that the error mentions `coverageAmount`, so the failure is clearly tied to the missing required field. **What checks Copilot's output?** The project safety net is the test suite. I ran `npm test` locally, and the same suite runs in CI on every push, so AI-generated code is held to the same standard as human-written code.
